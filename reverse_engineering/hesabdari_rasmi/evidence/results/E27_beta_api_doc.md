## E27.1 دسترسی و احراز هویت
| گزاره سند | جزئیات |
|---|---|
| نشانی پایه | `api.rb24.ir/BeTA` در متن؛ `https://api.rb24.ir/beta/1.0/...` در جدول‌ها؛ یک نمونه cURL `.../beta/1/...` |
| احراز هویت | OAuth2 از «بانکداری باز»: `POST https://api.rb24.ir/connect/token` با `grant_type`، `client_id`، `client_secret`. پاسخ: `access_token`، `expires_in`، `token_type`، `scope` |
| قالب بدنه توکن | جدول: JSON. نمونه cURL: `application/x-www-form-urlencoded`. **ناسازگار** |
| سرآیندها | `Authorization: Bearer <token>` و `apikey: <API-KEY از سامانه بتا>`. نمونه‌های cURL `Authorization: true` دارند. یادداشت: «در هدر تمام سرویس‌ها Token و TerminalName (= ClientId) دریافت می‌گردد» |
| خطاهای HTTP | 403 مجوز ندارید؛ 400 خطای اعتبارسنجی؛ 500 خطای سیستمی. **خطای کسب‌وکاری با HTTP 200** و در فیلد `status` پاسخ برمی‌گردد |

## E27.3 مدل داده رسمی
- `Order { long Id; string Title; long Amount; string CustomerNationalCode; string Description; ProjectTypeEnum ProjectType }` — **بدون** تاریخ ثبت، تعداد اقساط، وضعیت، شناسه نماینده یا ثبت‌کننده.
- `ProjectTypeEnum { RefahKala = 0, AlmasRefah = 1 }` در سرویس ۴؛ در سرویس ۱۰ `TaraWallet = 3` هم هست. سند آن را «نوع مشتری» می‌نامد. معنای «AlmasRefah» در سند توضیح داده نشده است.
- `Installment { long Id; long Amount; DateTime OverdueDate; DateTime? SettelDate; bool IsSetteled; int OrderId; InstallmentStatusEnum Status; string StatusTitle; bool IsDeleted }`.
- `InstallmentStatusEnum { Created /*پردازش نشده/ثبت شده*/, InProcess /*در حال پردازش برای وصول*/, Success /*وصول موفق*/, Rejected /*وصول ناموفق*/ }` — **بدون مقدار عددی**.

## E27.4 قواعد و محدودیت‌های صریح
1. توان بازپرداخت «**ماهیانه** … تا لحظه استعلام» است. شرط آن تکمیل احراز هویت مشتری در بتاست. نبود اهلیت اعتباری (چک برگشتی، اقساط معوق، مسدودی حساب) یعنی توان = صفر.
2. «سقف برداشت از حساب مشتری به میزان پیش‌بینی توان بازپرداخت است». اقساط **از حساب مشتری برداشت و به حساب پذیرنده منظور** می‌شود (برداشت خودکار).
3. رمز یکبار مصرف **۲ دقیقه** اعتبار دارد و تا وقتی معتبر است، رمز تازه صادر نمی‌شود (4444). رمز **به داده‌های ورودی حساس است**: هر تغییر آن را باطل می‌کند.
4. ثبت فروش به منزله **تأیید فروش از جانب مشتری و پذیرنده** است. پس از ثبت، پیامک جدول اقساط برای مشتری ارسال می‌شود.
5. حداکثر **۳۶** قسط (4462). حداکثر **۸ خرید در ماه** برای یک مشتری از یک پذیرنده (4463). مبلغ بیش از اعتبار (4461). درخواست تکراری (4406).
6. مشتری ثبت‌نام‌شده در یک «طرح» تا پایان آن طرح نمی‌تواند در طرح‌های دیگر شرکت کند (4455 در درخواست رمز و ثبت فروش).
7. خطاهای پذیرنده: 4470 (بدون مجوز api)، 4471 (یافت نشد)، 4473 (غیرفعال)، 4474 (مجاز به ثبت فروش/عملیات نیست)، 4775 (بدون تفاهم‌نامه فعال؛ احتمالاً 4475)، **4476 «کارمزد شما به درستی تعریف نشده است؛ به مدیریت امور شعب استان مراجعه کنید»**.
8. فهرست فروش همه فروش‌های ماه را برمی‌گرداند، «چه از طریق پنل، چه از طریق وب‌سرویس». صفحه‌بندی ندارد.

## E27.5 آنچه سند **نمی‌گوید** (پایه مجهولات U-B)
- هیچ سرویسی **واریز به حساب پذیرنده** (تاریخ، مبلغ، شناسه تراکنش) را برنمی‌گرداند.
- مبلغ، نرخ یا زمان **کارمزد بانک/سهم بانک** در هیچ سرویسی نیست. فقط 4476 وجود «کارمزد پذیرنده» را نشان می‌دهد.
- هیچ فیلدی برای **نماینده، بازاریاب یا ثبت‌کننده** در سرویس‌ها نیست. (در خروجی پنل، E15، ستون‌های «نمایندگی»، «بازاریاب» و «کدملی ثبت کننده» هست.)
- وب‌هوک یا اعلان رویداد وجود ندارد. وضعیت اقساط فقط با **پرسش دوره‌ای** (سرویس ۵) به دست می‌آید.
- قالب تاریخ‌ها (میلادی یا شمسی، منطقه زمانی)، حروف نام فیلدها (camelCase یا PascalCase)، قالب `startDateYearMonth` و پاسخ «یافت نشد» در سرویس ۱۰ مشخص نیست.
