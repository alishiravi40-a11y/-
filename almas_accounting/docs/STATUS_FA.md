- **سه اشکال واقعی پیدا و رفع شد:** کندی شدید پس از ورود دوم، ورود رهاشده که «در حال اجرا» می‌ماند، و خلاصه تغییرات نادرست ورود نخست و Backup تکراری.

- **آزمون‌ها:** ۷ آزمون تازه. کل: **۲۰۸ آزمون، همه قبول**.

### ۲۱. جلوگیری از دوباره‌شماری در هم‌زیستی (هسته v0.29؛ D-07 باز)
- تا مالک تاریخ شروع دفاتر رسمی سیستم جدید را تعیین نکند (تنظیم `book_of_record_from`)، هر سند سیستم جدید در ماهی که سند هلو هم دارد فهرست می‌شود (COEX-01).
- پس از تعیین تاریخ: سند هلو پس از آن (COEX-02) و سند جدید پیش از آن (COEX-03) فهرست می‌شوند.
- هیچ سندی خودکار حذف یا خنثی نمی‌شود.

### ۲۲. بازبینی از دید کاربر و حسابدار: کار روزانه بدون SQL و خط فرمان (هسته v0.30)
کار عادی دیگر به SQL، خط فرمان یا ابزار توسعه نیاز ندارد. آنچه پیدا و تکمیل شد:

| کمبود پیداشده | حالا |
|---|---|
| انبار، صندوق و حساب بانکی فقط با SQL تعریف می‌شد | صفحه «پایه‌ها»، با کنترل حساب‌ها (حساب اشخاص، حساب تکراری و حساب گردش‌دار رد می‌شوند) |
| فاکتور پس از ثبت دیده نمی‌شد؛ فقط سندش دیده می‌شد | فهرست فاکتورها، و نمایش و چاپ فاکتور و برگشت با سربرگ شرکت، مبلغ به حروف و جای امضا؛ ثبت برگشت از خود فاکتور |
| صورت‌حساب بانک فقط با خط فرمان و فقط یک قالب بانک وارد می‌شد | بارگذاری xls، xlsx یا CSV از صفحه مغایرت؛ هر فایل یک بار؛ بررسی زنجیره مانده |
| تطبیق خودکار بانک فقط با خط فرمان بود | دکمه «تطبیق خودکار موارد بی‌ابهام» و لغو هر تطبیق با علت |
| **تطبیق دستی بانک از رابط کار نمی‌کرد:** API فهرست را همیشه JSON می‌فرستاد | API به نوع پارامتر نگاه می‌کند (آزمون تازه) |
| انتقال بین صندوق و بانک، پرداخت هزینه و کارمزد بانکی صفحه نداشت | صفحه «انتقال وجه، هزینه و کارمزد» |
| Backup هلو فقط با خط فرمان وارد می‌شد | ارسال از مرورگر با نوار پیشرفت و اجرا در سرور؛ صفحه خودش به‌روز می‌شود |
| ساخت سال مالی بعد، بستن سال و افتتاحیه صفحه نداشت | بخش «سال‌های مالی» در «سال‌ها و دوره‌ها» |
| ضایعات و کسری انبار راهی نداشت | صفحه ضایعات با قاعده هلو (E17) و برگشت از کارت کالا |
| برگرداندن تخصیص و برگرداندن انتقال انبار صفحه نداشت | فهرست تخصیص‌ها با «برگرداندن» و دکمه برگشت در کارت کالا |
| چاپ و خروجی Excel نبود | سربرگ شرکت روی هر چاپ؛ «خروجی Excel» روی هر جدول |
| روش پرداخت فاکتور همیشه «نقد» ثبت می‌شد، حتی با انتخاب بانک | روش از حساب انتخاب‌شده می‌آید (سند درست بود؛ فقط برچسب غلط بود) |
| ورودِ رهاشده با خاموشی سرور جلوی ورود بعدی را می‌گرفت | پس از خاموشی سرور، ورود رهاشده «ناموفق: قطع شده» بسته می‌شود و ورود بعدی از همان‌جا ادامه می‌دهد |

**آزمون در مرورگر:**
- **داده ساختگی:** ۳۳ بررسی، همه قبول و بدون خطای صفحه. مسیر: حساب ← صندوق و انبار ← شخص و کالا ← خرید ← فروش با دریافت ← نمایش و چاپ فاکتور ← برگشت از فاکتور ← فهرست و خروجی Excel ← انتقال وجه، هزینه و کارمزد ← بارگذاری صورت‌حساب، تطبیق خودکار و لغو ← انتقال انبار و برگشت آن ← ضایعات و برگشت آن ← دریافت، تخصیص و برگرداندن آن. با کاربر مدیر و ورود دومرحله‌ای: مشخصات شرکت ← ساخت سال ۱۴۰۶ ← بستن ۱۴۰۵ ← افتتاحیه ۱۴۰۶.
- **Backup واقعی ۱۴۰۴ از مرورگر** در یک پایگاه آزمایشی جدا:
  - ارسال ۴۲۶ مگابایت چند ثانیه طول کشید.
  - در میانه کار، محیط اجرا خاموش شد. پس از راه‌اندازی دوباره، ورودِ نیمه‌کاره خودکار «ناموفق: قطع شده» بسته شد.
  - ارسال دوباره همان فایل از همان‌جا ادامه داد و حدود ۱۰ دقیقه بعد **تطبیق کامل** شد: هر ۸ کنترل برابر بود، از جمله ۱۰,۰۳۸ کد با View خود هلو و ۴۷,۴۴۷ سند. اعداد همان اجرای خط فرمان E30 است.

**آزمون‌ها:** ۱۱ آزمون تازه. کل: **۲۱۹ آزمون، همه قبول**.

## گزارش نهایی: چه کار می‌کند و چه چیزی هنوز جلوی استفاده روزانه واقعی را می‌گیرد
**کار می‌کند و با آزمون و تطبیق اثبات شده:**
- دفتر، اشخاص، چک، کالا، مؤدیان و تسویه ۱۴۰۴ برابر هلو (E24، E30)؛
- ورود هر Backup تازه با تشخیص تغییر، بدون ویرایش سابقه، بدون ثبت تکراری و با تطبیق کامل؛
- **همه** عملیات روزانه، تنظیم پایه‌ها، ورود صورت‌حساب بانک و Backup هلو، بستن سال، چاپ و خروجی Excel از رابط فارسی، بدون SQL یا خط فرمان (بخش ۲۲)؛
- نمایندگان و بتا بر پایه تصمیم‌های بسته‌شده (D-22 بخش اصلی، D-25)؛
- ورود امن با رمز Argon2id، ورود دومرحله‌ای و کلید سرویس.

**هنوز مانع استفاده روزانه واقعی است:**
1. **استقرار (فنی، بدون تصمیم کسب‌وکاری):** سرور داخلی با TLS، نقش محدود پایگاه داده به‌جای کاربر مدیر، پشتیبان‌گیری خودکار و آزمون بازگردانی، و پایش. تا این انجام نشود، سیستم فقط محیط آزمایشی است.
2. **D-07، تصمیم مالک:** از چه تاریخی سیستم جدید دفتر رسمی است و فاز موازی چقدر است. تا آن زمان سیستم فقط «دفتر سایه» کنار هلو است و ثبت روزانه در آن دوباره‌شماری می‌سازد (COEX-01 آن را نشان می‌دهد).
3. **Backup ۱۴۰۵ (D-09):** برای شروع کار در سال جاری، اسناد ۱۴۰۵ و مانده‌های افتتاحیه آن لازم است. مسیر ورودش آماده و آزموده است.
4. **ارسال به سامانه مؤدیان:** سیستم جدید سابقه ارسال را نگه می‌دارد و کنترل می‌کند، ولی به پرتال وصل نیست. تا وصل نشود، فاکتور فروش رسمی باید از هلو یا پرتال فرستاده شود.
5. **بتا و نماینده:** ثبت حسابداری و مالیاتی سهم نماینده و بانک منتظر D-14، D-22a تا D-22e، D-26 و D-27 است. فهرست ۱۱ ثبت‌کننده پنل و نمایندگانشان هم لازم است. اتصال API بانک منتظر نسخه جاری از بانک است (D-23).
6. **بازبینی کاربری روی دفتر واقعی** توسط مالک و حسابدار، و ورود دستی ضامن‌های باز (W-35).
7. **کمبودهای غیرمسدودکننده که مانده:**
   - در سابقه ردیف‌ها کاربر پایگاه داده نشان داده می‌شود، چون نقش محدود هنوز مستقر نشده (بند ۱).
   - نخستین کاربر مدیر هنگام نصب با یک دستور ساخته می‌شود (بخش استقرار). پس از آن، همه کاربران از رابط ساخته می‌شوند.
   - قالب چاپ پیش‌فاکتور و چاپ چک نداریم.
   - قیمت فروش پیش‌فرض کالا نداریم؛ قیمت در هر فاکتور وارد می‌شود.
