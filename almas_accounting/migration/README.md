# migration — انتقال دفاتر هلو به هسته جدید (D-03)

`holoo_ledger.py` درخت حساب، اشخاص و **همه اسناد یک سال مالی** را از `holoo_mirror` به هسته (`core`) منتقل می‌کند. جدول‌ها در `core/schema/005_legacy_ledger.sql` هستند.

## قواعد
- **D-03:** حساب شخص در هسته «حساب» نیست. ردیف روی حساب کنترلی می‌نشیند و شخص روی ردیف مشخص می‌شود (`party_id`):
  - تفصیلی شخص زیر معین M ← حساب کنترلی M. اگر M حساب غیرشخصِ **دارای گردش** هم داشته باشد، کنترلی `M P` ساخته می‌شود.
  - معینِ شخص زیر کل K (کدینگ قدیمی) ← حساب کنترلی `KP`.
  - حساب‌های غیرشخص با همان کد هلو می‌مانند. تفصیلی غیرشخصِ بدون گردش زیر معین شخص در نگاشت با وضعیت `dropped_unused` ثبت می‌شود.
- **Lineage:** `legacy_account_map` برای هر کد هلو و `legacy_entry_map` برای هر سند هلو (هش سند، Import اول و آخر) نگه داشته می‌شود. `party_legacy_code` هم از `beta/legacy.py` می‌آید.
- **Idempotent:** اجرای دوباره همان Import هیچ تغییری ایجاد نمی‌کند. در Backup جدیدتر همان سال:
  - سندی که تغییر کرده، با **سند معکوس + سند جدید** جایگزین می‌شود و هرگز ویرایش نمی‌شود؛
  - سند حذف‌شده در منبع **معکوس** می‌شود.
- ردیف‌های پنهان (ابطال فاکتور) و ردیف صفر منتقل نمی‌شوند. سندی که ردیفی برایش نماند با وضعیت `skipped_no_visible_lines` ثبت می‌شود.
- در `holoo_mirror` هیچ نوشتنی انجام نمی‌شود و Reader و Restore هلو دست‌نخورده‌اند.
- انتقال از قواعد عادی هسته عبور می‌کند: توازن سند، حساب برگ، الزام شخص، دوره باز و تغییرناپذیری سند ثبت‌شده. Audit زنجیره‌ای هم فعال است.

| مورد | نتیجه |
|---|---|
| درخت حساب | ۸۳۷ حساب هسته: ۸۳۵ کد هلو و ۲ حساب کنترلی `103P` و `401P`. ۲۲ حساب نیازمند شخص. ۳۲,۷۰۵ حساب شخصی هلو به `person_control` نگاشت شد و ۲۴ حساب بی‌گردش `dropped_unused` است |
| اشخاص | ۳۲,۶۹۶ پرونده (همان نگاشت `beta/legacy.py`) |
| اسناد | ۴۷,۴۳۹ سند و ۱۹۰,۴۴۷ ردیف ثبت شد. ۸ سند بدون ردیف قابل‌دیدن بود (ابطال‌شده). جمعاً ۴۷,۴۴۷ سند، برابر هلو |
| برابری با آینه | ۹,۹۵۶ (حساب، شخص): **صفر اختلاف**. جمع بدهکار و بستانکار هر دو 80,719,765,143,371 |
| **برابری با View خود هلو (`MandehOfSarfasl`)** | **۱۰,۰۳۸ کد در سطح کل، معین و تفصیلی (شامل هر شخص): صفر اختلاف** (`verify_holoo_view.py`) |
| اجرای دوباره | صفر تغییر (۳ ثانیه). اجرای اول ۵۲۲ ثانیه |
| Audit | ۹۴,۸۷۹ رویداد و زنجیره هش سالم |

## آزمون‌ها
`migration/tests` (۵ آزمون، Mirror ساختگی):
- ساختار D-03؛
- برابری و سند ابطال‌شده؛
- اجرای دوباره بی‌اثر؛
- Backup جدیدتر: جایگزینی سند تغییریافته، معکوس کردن سند حذف‌شده، و ماندن سابقه؛
- تغییرناپذیری سند منتقل‌شده؛
- دست‌نخوردن Mirror.

اجرا:
```bash
python -c "import psycopg; from migration import holoo_ledger as M; c = psycopg.connect(DSN, autocommit=True); print(M.migrate(c, 'holoo1_1404', '1404')); print(M.parity(c, 'holoo1_1404'))"
python -m migration.verify_holoo_view --pg DSN --source-db holoo1_1404 --sql-db <restored Holoo DB>
```
